## 代码优化审查（未修改代码）

通读了整个项目（36 个 Java 类、10 个 Thymeleaf 模板、css/js、sql），产出 `docs/优化审查清单.md`，按 P0~P4 分级列出 32 项问题。用户要求先只审查、不改代码。

定位到的关键缺陷（后续改造时可直接参考）：
1. profile 收藏列表渲染冲突 —— `main.js:loadFavorites()` 覆盖 `#favoritesList.innerHTML` 销毁 `#favoritesContainer`，profile.html 内联同名函数随后取到 null 抛错 → 恒显示"暂无收藏"。
2. 实时天气接口不返回 tempMax/tempMin/uvIndex，但 index/detail 页在展示 → 恒为 `--`。
3. 预警只增不删：`getActiveWarnings` 不判 endTime，生成无去重，定时任务每 6h 重复插入。
4. AI 模块名不副实：ai-forecast 页展示的是和风原始 7d 数据，AiPredictionService 产出无前端入口。
5. 统计页无数据时用 CLIMATE_NORMALS + Random 合成，且 Controller 内同步循环 12 个月生成，首屏慢。
6. 每次访问都 save 天气数据且 weather_data 无唯一键 → 数据膨胀 + 无缓存导致首屏慢。

改造优先级建议：先修 1/2/3，再加缓存层（Caffeine，TTL 10-30min）+ 唯一索引 upsert，再把 AI 预测接入页面，最后做 UI 一致性与代码去重。
