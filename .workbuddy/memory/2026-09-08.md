## 15:30 模板里发现 data-page-node-id 注入

用户报"搜索没有反应"。第一轮我以为只是 error.html 的 inline 拼接问题（修了 0ae2198/1d59117），结果搜索仍 500。

第二轮回溯：用 Read 看完整 warnings.html，第 123 行 Thymeleaf 表达式被工具/IDE 注入的 `data-page-node-id="MnFPJkmk56eD5kTZ3E0UF4"` 卡进了 lambda 中间：

```
${list.stream().mapToInt(c - data-page-node-id="MnFPJkmk56eD5kTZ3E0UF4"> c['warningCount'] != null ? c['warningCount'] : 0).sum()}
```

`c ->` 被切成 `c - ...>`，整段表达式无效 → Thymeleaf 解析失败 → /error → 错误页报第二个错覆盖原始异常 → 浏览器一片空白。

修复：
1. 把 statistics 累加在 controller 里算好（`sumWarningCounts` helper），模板只读 `${totalWarnings}`，避开 OGNL stream()
2. warnings.html 第 123 行 `th:text="${totalWarnings}"` 替代 stream 表达式
3. 全局清理 380 处 `data-page-node-id="..."` 噪点（4 个模板：aether/fragments/index/warnings），Python 批量正则一次解决

教训：
- 看到 Thymeleaf 报错时，先 `grep -rn "data-page-node-id" src/main/resources/templates/` 看是不是有工具/IDE 注入到表达式内部
- Thymeleaf 默认会把 `data-page-node-id` 当普通 HTML 属性，不会报解析错误；只有当它被注入到 `th:*` 值内部时才致命——这种隐藏 bug 看 stack trace 抓不到，必须读源码
- OGNL stream() 在 Thymeleaf 里能跑但不稳（依赖 JSONArray.spliterator 行为），controller 里算好聚合更可靠
