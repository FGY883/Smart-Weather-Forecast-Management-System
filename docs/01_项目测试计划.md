# 项目测试计划

## 1. 项目基本信息

- 项目名称：基于 Spring Boot + Thymeleaf + AI 的智能天气预报系统（Maven 坐标 `com.weather:smart-weather-forecast`）
- 项目版本：1.0.0
- 测试负责人：FGY（开发自测，无独立测试角色）
- 编写日期：2026-09-22

## 2. 项目简介

本系统面向需要日常天气信息的普通用户与毕业设计评审场景，解决"天气查询分散、缺乏趋势预测、极端天气通知滞后"三类问题。系统以 Spring Boot 2.7.18 + Thymeleaf 服务端渲染为主干，MySQL 8.0 + MyBatis-Plus 持久化，Spring Security 负责认证授权；上游接入和风天气（实况、7 天预报、历史、城市地理编码）与华风爱科（灾害预警）两类外部数据源。核心功能覆盖用户注册登录与个人中心、城市搜索与实时天气展示、7 天预报、基于线性回归与移动平均融合算法的 AI 趋势预测、按阈值自动判定的四级极端天气预警、城市收藏与每日推送、月度统计与 ECharts 可视化，以及手绘风格的城市天气卡片页。项目共 10 个页面模板、4 个控制器、8 张数据表、3 个定时任务。

## 3. 测试目标

本次测试以"答辩演示可用 + 数据链路可信"为总目标，重点验证以下质量目标：

1. **功能正确性（最高优先级）**：注册登录、城市搜索、实时天气、7 天预报、AI 预测、预警查询、收藏与推送、统计可视化八条主链路在真实数据源下可走通，页面不出现 `--`、空白卡片、报错堆栈。
2. **数据真实性与可解释性**：区分"实况/预报真值""AI 预测值""历史统计估算值"三类数据，估算与降级生成的数据必须在界面上可识别（`estimated` 标记、置信度展示），不得把合成数据当作实测数据呈现。
3. **外部依赖容错与接口稳定性**：和风 / 华风接口超时、限流、返回字段缺失或 Key 失效时，系统需降级为可读提示而非 500 页面，且不写入脏数据。
4. **算法正确性**：AI 预测与预警阈值的计算结果可用公式复算验证，边界值判定准确。
5. **安全基线**：认证授权不可绕过、越权访问被拦截、CSRF 与暴力破解有实际防护效果、无敏感信息泄漏到前端或日志。
6. **移动端与浏览器可用性**：10 个页面在 375px / 768px / 1440px 三档宽度与 Chrome / Edge / Firefox 下无横向滚动、无错位、图表可渲染。
7. **性能与配额可持续性**：首屏响应可接受，缓存命中率生效，单日和外部 API 调用次数不超出免费版 1000 次/天配额。

**不做为通过标准的项**：不追求零缺陷；已知 P2/P3 级代码质量问题（重复代码、`Result` 缺时间戳、Lombok 未重构）不计入本次通过判定。

**出口标准**：P0 缺陷 0 个遗留、P1 缺陷遗留 ≤2 个且有规避说明、八条主链路冒烟用例全部通过、全部风险项在交付物中有记录。

## 6. 测试方法与进度

### 6.1 各类型测试方法

1. **功能测试（手工黑盒 + 场景化用例）**
   按第 4 节模块顺序，以"未登录 / 普通用户 / 禁用用户 / 关闭推送用户"四种身份各跑一遍八条主链路。每条用例记录 URL、操作、预期与实际，重点观察三类降级提示是否可读、页面是否出现 `--` 或空白卡。城市卡、预警、统计的边界值用 SQL 直接改写 `weather_data` / `weather_warning` 的观测值来构造（高温 32.9/33/34.9/35、寒潮 0/−10、暴雨 29.9/30/49.9/50、风速 79/80），以确认阈值判定不依赖真实天气即可复现。
2. **接口测试**
   对 27 个路由（页面与表单路由 19 个、返回 JSON 的接口 8 个：`/api/favorite/add|remove|list`、`/api/prediction/generate`、`/api/warning/active|all`、`/api/push/records`、`/api/aether/weather`）用 curl + Postman 验证：统一返回体 `Result{code,msg,data}`、HTTP 状态码、未登录时的 401 与 302 差异、必填参数缺失、越权访问他人收藏。特别核对 `/api/prediction/generate`、`/api/warning/active`、`/api/warning/all` 在无会话下的实际拦截行为（控制器未做用户判空，依赖 Security 规则）。异常路径断言：由于 `GlobalExceptionHandler` 对所有异常返回 HTML 错误视图，需记录前端 JS 拿到 HTML 而非 JSON 时的实际表现。
3. **单元测试（本次新建）**
   在空的 `src/test` 下用 JUnit 5 + Mockito 建立算法与工具层用例，优先覆盖纯逻辑与可构造输入：`AiPredictionUtil`（回归、加权移动平均、融合权重、钳制边界、置信度分档、<3 点退化）、`WeatherWarningServiceImpl` 阈值分支（mock `WeatherDataService`）、`LoginAttemptService`（窗口/计数/锁定）、`UserController` 校验正则、`WeatherCache`（TTL 过期、null 不缓存）、`WeatherApiUtil` 字段缺失时的解析健壮性。目标：`com.weather.util` 行覆盖 ≥70%，算法核心分支覆盖 ≥80%，不追求 Controller 层覆盖率。
4. **自动化冒烟**
   用 `@SpringBootTest` + MockMvc 为每个 GET 路由写一条"200 且含关键标识"的冒烟断言（约 10 条），配合 `mvn test` 作为改动回归门禁；上游接口以 WireMock 或 Mockito 打桩，避免消耗配额。页面级端到端仅对登录→搜索→收藏→个人中心一条主流程尝试 Playwright，若时间不足则降级为手工。
5. **移动端与响应式测试**
   DevTools 设备模拟三档宽度遍历 10 页，检查 `viewport` 生效、导航可折叠、双列信息卡不挤压（`detail.html`）、ECharts 图表随 `resize` 重绘且无监听器堆积；再用真机（Android Chrome / iOS Safari）验证登录与图表可交互。
6. **安全测试**
   越权：改 `favoriteId` / 他人 `cityCode` 访问收藏与推送记录；未登录访问 `/user/profile`、`/api/favorite/list`；CSRF：去掉 token 提交 `/register`、`/user/profile`（应拒绝），并验证 `/api/aether/**` 白名单范围仅限只读查询；暴力破解：连续 5 次错密码后**用正确密码**再登录一次，验证 `LoginAttemptService.isLocked()` 从未被调用是否导致锁定形同虚设；XSS：昵称、搜索词、城市名填入 `<script>`/`onerror` 检查所有回显点；注入：搜索与城市编码填入 `' or 1=1 --`；信息泄漏：错误页与日志不外泄堆栈、API Key 不出现在前端源码与响应中。
7. **性能与配额测试**
   冷启动与热缓存下分别记录首页、详情、统计页的服务端耗时（DevTools Network + 日志）；用 `curl` 串行 20 次与并发 20 线程各测一轮，统计上游调用次数（验证缓存是否命中、`getOrLoad` 非原子是否引起击穿重复请求）；`weather_data` 行数与 `weather_warning` 生效条数在 24 小时观察窗口内的增长，确认无无限膨胀；估算单日上游调用量对照和风免费版 1000 次/天上限。
8. **兼容性与数据校验**
   三浏览器遍历全页；确认 `schema.sql` / `data.sql` 中文与 BCrypt 初始账号写入无乱码；核对 `spring.sql.init.mode=always` 反复启动后的表与数据状态；统计页比对"估算标记 + 真实天数"与库内 `data_type` 分布的一致性（`countRealDataDays` 会把预报/回补行一并计入，需要如实记录该口径）。
9. **缺陷管理与回归**
   缺陷按 P0（演示当场失败/数据失真）、P1（功能不正确但有替代路径）、P2（体验与代码质量）三级记录于交付的缺陷清单，含复现 URL、身份、预期/实际、涉及文件行号。每轮修复后重跑 6.4 的冒烟集 + 该缺陷所在链路。

| 上游免费版配额（和风 1000 次/天）被测试与定时任务耗尽 | 实况/预报/历史接口 403，大面积用例无法执行 | 每轮测试前先执行一次连通性 curl；集中安排需要真实 API 的用例；用 `WeatherCache` 与直接改库构造数据，把 AI 回补、城市卡等重复调用降下来；必要时临时停用定时任务 |
| API Key 失效 / 上游域名（自定义 `*.re.qweatherapi.com` 与华风 `openapi.weathercn.com`）不可达 | 页面整体空态或降级提示，无法验证真值 | 备一份上游响应 JSON 作为桩数据；把"降级提示是否友好"独立成用例，即使真值不可测也能交付结论 |
| 编译环境不一致：`pom.xml` 为 JDK 8，`README.md` / 启动指南要求 JDK 11+，且历史上出现过 JDK 8 兼容性修补 | 依赖解析或编译失败，测试无法启动 | 统一在 JDK 8 与 JDK 17 下各跑一次 `mvn -DskipTests clean compile`，把结论写回文档；启动指南同步订正 |
| `AiPredictionUtil` 实现与 README 描述不符：README 称"70% 回归 + 30% 移动平均 + 正弦季节修正"，代码实为 0.6/0.4 融合且**无季节修正** | 按文档写的用例全部判为失败，或误报缺陷 | 以代码为准建立算法用例（0.6/0.4、斜率 ±0.5、0.88ⁱ 衰减、[min−4,max+4]），并在测试报告中单列"文档与实现不一致"缺陷，要求改文档而非改算法 |
| 预警阈值单位口径存疑：`windThreshold=8` 在代码中乘 10 得 80km/h | 大风预警几乎不可能触发，误判为功能失效 | 通过改库注入风速构造用例；在报告中确认口径并在配置中显式注明实际阈值 |
| 暴力破解锁定可能无效（`isLocked()` 定义了但认证流程未调用） | 安全测试判为 P1 失败，答辩被追问 | 优先构造用例坐实结论；若确认，最小改动在 `CustomUserDetailsService` 或失败/成功处理器中前置校验锁定态，否则在报告中明确风险 |
| 统计页在缺真实数据时会用气候常量 + 固定种子随机生成，且 `estimated` 口径为"真实天数 <28"并把预报/回补行也计入 | 结论被质疑数据造假，属学术诚信风险 | 用例必须核对"估算标记 + 真实天数"在页面可见并可复算；清空 `weather_data` 观察生成的合成数据；报告如实说明生成条件，避免演示时误称实测 |
| 首次访问即写库、`weather_data` 无 `(city_code, weather_date, data_type)` 唯一键，靠应用层 upsert | 并发下重复行、数据膨胀导致统计口径漂移 | 20 线程并发压同一路由后统计行数；将无唯一索引列为已知风险并给出建议 DDL，不临时改库结构 |
| `spring.sql.init.mode=always` + `continue-on-error=true` 每次启动重跑脚本并吞错 | 建表失败被静默，后续用例误判为功能缺陷 | 启动后先跑 `SHOW TABLES` 校验 8 张表与预置账号；报告中固定 `SQL_INIT_MODE` 取值 |
| Bootstrap、Bootstrap Icons、ECharts、Google Fonts 仍走公网 CDN（`aether.html` 引 Google Fonts，`ai-forecast`/`statistics` 引 jsdelivr） | 断网或墙内抖动时样式全崩、图表空白，演示当场失败 | 离线环境专项用例（DevTools 切 offline 复现）；准备 vendor 本地化清单，答辩前至少完成一次全离线走查 |
| 明文密钥与数据库口令已入库入 Git（`application.yml` 中两处 API Key、`123456`） | 安全缺陷 + 交付物泄漏风险 | 用 `WEATHER_API_KEY` / `WEATHERCN_API_KEY` / `DB_PASSWORD` 环境变量跑通即视为配置可用；文档与截图一律脱敏；报告中列为必须整改项，测试提交物不含真实 Key |
| `src/test` 为空，单测从零建立，时间可能不足 | 缺少算法层证据 | 按优先级压缩：先 `AiPredictionUtil` + 预警阈值 + `LoginAttemptService`，其余以接口测试代替，并在报告中说明未覆盖范围 |
| 定时任务窗口（07:00 / 每小时 / 每 6 小时）难以在测试时段触发 | 推送与预警链路无法验证 | 用可配置 cron 覆盖（测试期临时改为 `*/2 * * * * ?` 或启动时执行一次）验证后回滚，把配置项与回滚记录留存 |
| 收藏与推送为"库内模拟推送记录"，非真实触达 | 用例误判为推送失败 | 断言以 `push_record` 落库与列表展示为准；范围表已注明真实通道不测 |
| 缺陷修复引入回归（历史上 UI 曾整体回退过一次） | 修一处坏一片 | 6.4 的 MockMvc 冒烟集 + 手工 10 页快速走查作为每次修改后的固定回归；保持每轮改动独立提交便于回滚 |

## 8. 交付物

本项目最终提交以下测试交付物（均置于项目 `docs/` 目录，随代码一同版本管理）：

1. `docs/01_项目测试计划.md` —— 本文件，含范围、环境、方法与进度。
2. `docs/02_测试用例与执行记录.md` —— 按模块的用例表（用例号、前置、步骤、预期、实际、状态、执行人、日期），覆盖第 4 节全部模块。
3. `docs/03_缺陷清单.md` —— P0/P1/P2 三级缺陷，含复现 URL、身份、涉及文件:行号、是否已修复与验证结论。
4. `docs/04_接口测试集` —— Postman Collection JSON 与等价 curl 脚本（8 个 JSON 接口 + 关键页面路由，各含正常/异常/越权三组），响应样例脱敏后入库。
5. 自动化测试代码 —— 新增 `src/test/java/com/weather/...` 下的 JUnit 5 + Mockito 用例与 MockMvc 冒烟集，附 `mvn test` 通过截图与覆盖率数据。
6. `docs/05_性能与安全测试记录.md` —— 冷/热缓存耗时、并发与上游调用次数、`weather_data` 与 `weather_warning` 行数观察、安全检查表逐项结论。
7. 多端兼容性截图 —— 10 页 × 375/768/1440px 三档的页面截图，以及离线（CDN 不可达）状态截图。
8. `docs/06_测试总结报告.md` —— 出口标准达成情况、遗留缺陷与规避说明、文档与实现不一致项（JDK 版本、和风域名、预警数据源、AI 季节修正描述）、后续改进建议。
9. 演示环境检查清单 —— 答辩前一次性核验项：建库与预置账号、两个 API Key 连通、`SQL_INIT_MODE`、网络与 vendor 资源、测试账号口令、定时任务状态。
