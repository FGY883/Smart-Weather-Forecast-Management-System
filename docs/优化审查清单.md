# 智能天气预报系统 — 优化审查清单

> 审查范围：`src/main/java`（36 个类）、`templates`（10 个页面）、`static`（css/js）、`application.yml`、`sql/`
> 审查日期：2026-09-08　|　结论：功能骨架完整，但存在 6 个会直接影响演示效果的功能/数据缺陷，建议按 P0→P4 顺序处理。

## P1　性能与稳定性

7. **HTTP 客户端**：`doGet` 每次 `HttpClients.createDefault()`，无连接池、无 connect/read 超时、无重试。外部接口抖动会拖死 Tomcat 线程。改为单例 `PoolingHttpClientConnectionManager` + `RequestConfig`。
8. **无全局异常处理**：缺少 `@ControllerAdvice`；多处 `catch (Exception ignored) {}` 吞掉异常（如 `WeatherController:245,258`），排查困难。
9. **定时任务单线程**：`@Scheduled` 未配置线程池，`dailyPredictionAndPush` 对每个用户串行调用 AI 预测（每用户最多 30 次历史 API），会阻塞 `collectWeatherData`。另：采集任务遍历收藏表未对城市去重，同一城市被重复采集 N 次。
10. `AetherController:81` 用 `parallelStream` 跑网络 IO，占用公共 ForkJoinPool，建议改为自定义线程池。
11. **列表无分页**：收藏、推送记录、预警列表均全量返回。

## P2　安全与配置

12. **CSRF 全局关闭 + GET 退出登录**：一枚 `<img src="/logout">` 就能让用户被登出。建议保留 CSRF（Thymeleaf 表单天然带 token），退出改为 POST 表单。
13. **明文密钥**：`application.yml` 中数据库密码 `123456`、和风 API Key 直接入库入 Git。改为 `${WEATHER_API_KEY}` 环境变量。
14. `spring.sql.init.mode=always` + `continue-on-error=true`：每次启动都跑 schema/data 且吞错，生产环境危险，建议按 profile 区分。
15. `maximumSessions(1)` 未配 `SessionRegistry`/`HttpSessionEventPublisher`，实际不生效；`antMatchers("/admin/**")` 无任何对应路由（死配置）。
16. 登录/注册无限流、无验证码，可暴力破解；注册只校验密码长度，用户名/邮箱/手机无格式校验，失败统一提示"用户名已存在"（可能是其它原因）。
17. 上线前应关闭 `mybatis-plus.configuration.log-impl: StdOutImpl` 与 `logging.level.com.weather: debug`。

## P3　前端 UI / 交互

18. **7 天预报卡场景写死**：`index.html:217` 的 class 硬编码 `sky-cloudy`，所有日期都是同一种天空。后端已有 `WeatherCardService.sceneOf()`，前端应复用它按 `day.weatherText` 映射。
19. **预警等级/类型展示不一致**：`warnings.html` 做了"红色预警/高温"中文映射，`index.html:69-72` 和 `detail.html:60-63` 却直接显示 `RED`、`HIGH_TEMP`。
20. **导航四个菜单指向同一页**："个人中心 / 个人信息 / 我的收藏 / 推送记录"全部 `th:href="@{/user/profile}"`。
21. **Aether 场景绘制代码重复**：`aether.html:420-587` 与 `aether-card.js:7-135` 的 `SCENES / cloudGroup / rainLayer / snowLayer / starLayer / birdLayer / buildScene` 几乎逐行相同（约 200 行）。
22. **收藏数据源冲突**：`aether.html` 用 localStorage 恢复城市列表且优先级最高，登录后后端返回的收藏城市不会生效。
23. **强依赖 CDN**：Bootstrap、ECharts、Google Fonts 全走公网（Google Fonts 国内尤慢）。答辩断网 = 样式全崩。建议本地化并配降级字体栈。
24. `toggleFavorite` 在 `index.html`、`detail.html`、`main.js` 各有一份；"取消收藏"要先 `list` 再 `remove` 两次请求，应新增按 `cityCode` 删除的接口。
25. 图表无 loading 骨架；`statistics.html` 四个图各注册一个 `resize` 监听，未做防抖。
26. **模板被注入垃圾属性**：`fragments.html`、`aether.html` 布满 `data-page-node-id="..."`，建议清理（显著增大模板体积）。
27. 细节：页脚 `© 2026` 硬编码；无 favicon（控制台 404）；无深色模式；`avatar` 字段闲置、头像不可上传；`detail.html` 移动端双列信息卡偏挤。

## P4　代码质量 / 可维护性

28. `WeatherController` 中"装配 6 张城市卡"的代码复制了三遍，且热门城市列表前后不一致（首页含西安，搜索/详情页含北京）→ 抽成一个私有方法 + 常量。
29. `getCurrentUser()` 在 `WeatherController`、`UserController`、`ApiController`、`AetherController` 重复四遍 → 抽到公共基类或 `UserContext` 工具类。
30. 30 城编码硬编码在 `WeatherCardService` 静态块、`AetherController.DEFAULT_CITIES`、`aether.html CITY_LIB` 三处，容易不同步 → 外置为配置或城市表。
31. `WeatherWarningServiceImpl` 里 `33 / 30 / -10` 等阈值写死在代码中，未走 `@Value` 配置（`rain-threshold`、`wind-threshold` 反而配了却没用上）。
32. 其它：`Result` 无 timestamp 与错误码枚举；`calculateConfidence` 用 `1 - stdDev/20` 缺依据；`AiPredictionServiceImpl:67` 每次生成预测都可能触发 30 次历史 API 调用。

## 建议的改造顺序

1. 先堵 P0 的 6 个洞（1~2 天），尤其是 #1 #2 #3——这三个在答辩演示时最容易当场露馅。
2. 加一层**天气数据缓存 + 唯一索引 upsert**（Spring Cache / Caffeine，TTL 10~30 分钟），这一项能同时解决 P0-6、P1-9 的大部分体感问题。
3. 把 AI 预测结果真正接入 `ai-forecast` 页（官方预报 vs AI 预测双曲线对比），让"AI"名副其实。
4. 再做 UI 一致性（场景映射、预警中文映射、CDN 本地化）和代码去重。
